# Drift tests — the deploy and CI inventory

The enumeration behind two entries in
[ARCHITECTURE.md](../ARCHITECTURE.md#project-layout). Both directories hold
**drift tests**: they assert that a unit file, a workflow, or a script still
says what the docs claim it says, so a silent configuration change fails a test
rather than a deployment.

They live here rather than in the module inventory because they enumerate
*assertions*, not responsibilities — the list turns over whenever a test is
added, while the inventory entry beside it does not.

## `tests/deploy/`

```
tests/deploy/                — Drift tests for the deploy surface: `deploy/notifier-sweep{,-dev}.{service,timer}` and `scripts/sweep.sh` in `test_sweep_units.py` (the production sweep carries the opt-in and the dev sweep never does; both launch through the one script; the timers fire often enough to bound alert latency, pin `AccuracySec`, and start themselves after a reboot; each service is `Type=oneshot` with a `TimeoutStartSec`, because systemd skips a firing while the last run is still going and a wedged endpoint would silently stop every subsequent sweep), `scripts/dev_server.sh` (guard delegation, safe env loading, port 9001, the tailnet bind reaching uvicorn, refusal paths, the `NOTIFIER_DEV_RELOAD` toggle exercised through a fake-`uv` PATH shim, and that no doc has regrown the unguarded recipe), `scripts/tailnet_bind.sh` (probes `/proc/net/fib_trie` and never a netlink client, bounded wait that fails non-zero rather than falling back to a wider bind, address on stdout only), `deploy/notifier.service` (opt-in flag in the unit and in no env file, ExecStart is `serve.sh` not a uvicorn line, ordered after tailscaled, restart loop bounded around the tailnet wait, and `NOTIFIER_BIND_HOST` baked into neither unit nor either env file), and `deploy/notifier-dev.service` (the opt-in flag is *absent*, ExecStart is the guarded script rather than a uvicorn line, reloader off, restarts bounded, ordered after tailscaled), and `scripts/install_qdrant_key.sh` in `test_install_qdrant_key.py` (the merge preserves unrelated settings, the write is atomic and owner-only, empty stdin is an error rather than an empty key, and two drift guards — the key never reaches a shell variable, and the script never traces itself, both scoped to executable lines so the comments warning against them do not match, a refused install writes nothing and creates no directory, and a global `core.excludesfile` is accepted where the repo's own rule is absent), and `.socraticode.json` plus the shared-store namespace in `test_socraticode_config.py` (project id is the repo name and Qdrant-safe, linked siblings are relative and name the cohort, `QDRANT_COLLECTION_PREFIX` and `SOCRATICODE_BRANCH_AWARE` are set in none of the six files that reach the MCP server's environment, `.claude/settings.local.json` is neither tracked nor un-ignored — two probes, because `git check-ignore --no-index` exits 0 for a path `git add -f` has staged, plus a control path proving both probes still answer — and a failing guard discloses no file contents, since two of the paths it reads hold secrets and pytest prints assertion operands in full under `-vv`, #73), and the auto-refresh hook's SessionStart budget in `test_skills_refresh_hook.py` (the entry is registered exactly once — the control without which the rest pass vacuously — and carries `120` as an integer, the constant from gregoryfoster/skills#259, pinned here because a wrong value is never repaired by re-running the installer, #71), and the SocratiCode health hook's budget in `test_socraticode_health_hook.py` (the same three assertions at `120`, plus a check that the constant still matches `--timeout` in the vendored `socraticode-health.install` — skipped where the submodule is uninitialized, as in CI, #75), and the SocratiCode server pin in `test_socraticode_pin.py` (the session's `SOCRATICODE_SPEC` in `.claude/settings.json` is a literal, matches the `~/.socraticode/pin` pre-install, and is the only spec `docs/SOCRATICODE.md` names; VS Code's machine-scoped `claudeCode.environmentVariables` carries the same value, because the settings block alone never reaches the plugin's launch — the pre-install and the machine setting are VM-local and skip in CI, #87), and the production memory reservation in `test_memory_reservation.py` (a floor rather than a cap, clearing the measured 90 MiB peak; both production units negative but above -1000 so they stay killable; the dev units carry none of it; and the earlyoom regexes asserted on the *split* argument vector, since the first spelling matched only quoted regexes and passed vacuously, #74; PostgreSQL's floor clearing its 121 MiB peak, and every slice above a floor granting exactly what its children claim, in the `[Slice]` or `[Service]` section its unit type reads — plus, live on this host only, each floor's *effective* value walked up the real `ControlGroup`, since every check that read the unit's own value passed while it was inert, #85)
```

## `tests/ci/`

```
tests/ci/                    — Drift tests for the build surface. `test_workflows.py` covers `.github/workflows/`; `test_dependabot.py` covers `.github/dependabot.yml` — the uv blocks span every table in `test_dependencies.py`'s `TABLES` (derived, so a new table fails here until dependabot covers it), the versioning strategy stays pinned to `increase-if-necessary`, dev churn stays grouped, and the workflows' actions are covered too, because a mistyped config stops producing PRs without erroring anywhere a person looks (#33); `test_dependencies.py` covers both dependency tables (this project's and `clients/python/`'s, which ships to consumers) — every specifier carries an upper bound, a `0.x` dependency caps inside its `0.x` line because pre-1.0 breaking changes land in minors, every runtime dependency has an importer under `src/` or an `IMPORT_LESS` entry naming why it is reached by name instead (#30), and — the mirror, by AST walk — every third-party module `src/` imports is declared rather than arriving transitively (#32). It asserts the conditions that make the gates meaningful and are invisible in the YAML: the test service database carries the `_test` suffix `db_safety` matches on, the migrations job uses a database pytest never touches (conftest's `create_all` would break `alembic upgrade head`), every job pins CPython 3.12 (`core = "sysmon"` falls back silently below it and reports ~6 points low against a live `fail_under = 80`), every job installs with `uv sync --locked` (#27), and the test job checks out with `fetch-depth: 0` — without which the release-tag gate below finds no tag, no `HEAD~1`, and passes vacuously; `test_version_lockstep.py` and `test_release_tags.py` cover the release surface (#50) — the service and the SDK carry one version, mirrored in (`pyproject.toml`, `src/api/main.py`'s `FastAPI(version=)`, the SDK's `pyproject.toml`, `__version__` and CHANGELOG heading), read rather than imported because `notifier_client` is not installed in this venv, and a released version must have a tag — with one commit of grace for the release commit itself, which is the window `v0.3.0` and `v0.3.1` were both lost in. The tag check refuses a shallow checkout outright rather than reporting green from one. `test_lint_selectors.py` covers `[tool.ruff.lint] select` (#66), the whole static-analysis surface between a commit and CI — `pre-commit` runs ruff and never pytest. It asserts `ASYNC` and `FAST` by name and the five baseline families as a set, because the evidence a clean run cannot supply is exactly the one that matters here: `ASYNC` reported 0 findings on the tree it was adopted against, so a green `ruff check .` looks identical whether the family is selected or silently gone. `test_doc_sensitive_paths.py` covers `.skills/doc-sensitive-paths`, the shipping skill's Step 1.5 path list: it replaces the vendored defaults wholesale, so an entry that matches no tracked file silently narrows the gate and reads exactly like a doc-neutral branch (#47); `test_doc_sections.py` covers `.skills/doc-sections`, the advice printed on a hit, which replaces its defaults the same way (#65) — it fails on a line naming a doc that is no longer tracked, and on a path the watch list flags that no line routes, the second being the coupling that stops a new sensitive path from arriving with no doc attached.
```
