# Drift tests — the deploy and CI inventory

The enumeration behind two entries in
[ARCHITECTURE.md](../ARCHITECTURE.md#project-layout). Both directories hold
**drift tests**: they assert that a unit file, a workflow, or a script still
says what the docs claim it says, so a silent configuration change fails a test
rather than a deployment.

They live here rather than in the module inventory because they enumerate
*assertions*, not responsibilities — the list turns over whenever a test is
added, while the inventory entry beside it does not.

## `tests/ci/`

```
tests/ci/                    — Drift tests for the build surface. `test_workflows.py` covers `.github/workflows/`; `test_dependabot.py` covers `.github/dependabot.yml` — the uv blocks span every table in `test_dependencies.py`'s `TABLES` (derived, so a new table fails here until dependabot covers it), the versioning strategy stays pinned to `increase-if-necessary` (because `auto` resolves to `widen` for the SDK, which uv does not support — not as a floor guard: under uv, in-range bumps raised floors anyway, #103), dev churn stays grouped, the uv block's `open-pull-requests-limit` exceeds every runtime PR plus every group PR open at once (derived from the tables, since past the limit dependabot opens nothing and says so nowhere — the default 5 silenced it for five weeks, #103), and the workflows' actions are covered too, because a mistyped config stops producing PRs without erroring anywhere a person looks (#33); `test_dependencies.py` covers both dependency tables (this project's and `clients/python/`'s, which ships to consumers) — every specifier carries an upper bound, a `0.x` dependency caps inside its `0.x` line because pre-1.0 breaking changes land in minors, every runtime dependency has an importer under `src/` or an `IMPORT_LESS` entry naming why it is reached by name instead (#30), and — the mirror, by AST walk — every third-party module `src/` imports is declared rather than arriving transitively (#32). It asserts the conditions that make the gates meaningful and are invisible in the YAML: the test service database carries the `_test` suffix `db_safety` matches on, the migrations job uses a database pytest never touches (conftest's `create_all` would break `alembic upgrade head`), every job pins CPython 3.12 (`core = "sysmon"` falls back silently below it and reports ~6 points low against a live `fail_under = 80`), every job installs with `uv sync --locked` (#27), and the test job checks out with `fetch-depth: 0` — without which the release-tag gate below finds no tag, no `HEAD~1`, and passes vacuously. It holds `sdk-staleness.yml` to firing on the root `pyproject.toml` and `uv.lock` too, since fastapi and pydantic shape `/openapi.json` as surely as `src/api/` does, and `audit.yml` to its job (#103): `uv audit --locked` over every table in `TABLES` (derived), one matrix leg per table with `fail-fast` off, the dev group never excluded, a daily schedule beside push and PR because advisories publish independently of commits, and a `canary` job auditing a known-vulnerable PEP 723 pin (`.github/audit-canary.py`) that passes only on exit 1 — so a uv release or an OSV outage that stops the gate biting turns it red rather than leaving it green; and no job or step in it carries `continue-on-error`, the one-line edit that would make both advisory. `test_version_lockstep.py` and `test_release_tags.py` cover the release surface (#50) — the service and the SDK carry one version, mirrored in (`pyproject.toml`, `src/api/main.py`'s `FastAPI(version=)`, the SDK's `pyproject.toml`, `__version__` and CHANGELOG heading), read rather than imported because `notifier_client` is not installed in this venv, and a released version must have a tag — with one commit of grace for the release commit itself, which is the window `v0.3.0` and `v0.3.1` were both lost in. The tag check refuses a shallow checkout outright rather than reporting green from one. `test_lint_selectors.py` covers `[tool.ruff.lint] select` (#66), the whole static-analysis surface between a commit and CI — `pre-commit` runs ruff and never pytest. It asserts `ASYNC` and `FAST` by name and the five baseline families as a set, because the evidence a clean run cannot supply is exactly the one that matters here: `ASYNC` reported 0 findings on the tree it was adopted against, so a green `ruff check .` looks identical whether the family is selected or silently gone. `test_doc_sensitive_paths.py` covers `.skills/doc-sensitive-paths`, the shipping skill's Step 1.5 path list: it replaces the vendored defaults wholesale, so an entry that matches no tracked file silently narrows the gate and reads exactly like a doc-neutral branch (#47); `test_doc_sections.py` covers `.skills/doc-sections`, the advice printed on a hit, which replaces its defaults the same way (#65) — it fails on a line naming a doc that is no longer tracked, and on a path the watch list flags that no line routes, the second being the coupling that stops a new sensitive path from arriving with no doc attached. `test_no_channel_urls.py` fails on a live Mayfly channel URL (id plus `#` key) in any tracked file, since this repo is public and the URL is the channel's read, write and delete credential; its pattern is assembled from a character class so it cannot match itself, and a planted-file control proves the scanner reads something (#89).
```
