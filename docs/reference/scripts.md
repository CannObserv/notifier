# Scripts — the per-script inventory

The enumeration behind the `scripts/` entry in
[ARCHITECTURE.md](../ARCHITECTURE.md#project-layout): what each script is
responsible for and why it is shaped that way. How to run each one, with its
flags, is in [COMMANDS.md](../COMMANDS.md).

```
scripts/                     — Helper scripts: `load_env.sh` (source it — the one env-loading recipe, resolves the repo `.env` from its own location so it works from any cwd), `dev_server.sh` (the only supported dev-server launch, used both by hand and as `notifier-dev.service`'s ExecStart — loads secrets, swaps in `DEV_DATABASE_URL`, runs the guard, requires `NOTIFIER_SECRET_KEY` so a missing key fails at startup instead of at first dispatch, checks migration state, then uvicorn on 9001; `NOTIFIER_DEV_RELOAD=0` drops `--reload` for the unit), `seed_tenant.py` (provision a **new** tenant + its first API key; prints `key_id` alongside the raw key so the credential can be retired later; production requires the opt-in flag), `rotate_key.py` (attach, revoke, or rotate a key on a tenant that already exists — `--list` to read the ids, both halves of a rotation in one transaction so an interruption cannot leave a tenant with no working key, `--dry-run`, and `--verify`/`--verify-old` to prove the new key 200s and the old one 401s against the real endpoint; revocation is a DELETE because a `revoked_at` filter fails open where a missing row fails closed, #62), `delete_tenant.py` (the only sanctioned way to delete a tenant — `--dry-run` names every key and counts what goes with them; `--expect-name` is required with `--yes`, since the ULID is the whole target and a typo naming another consumer deletes that consumer; every cascaded key lands on the credential audit channel the cascade bypassed entirely before #79), `copy_channels.py` (give a tenant copies of another tenant's channels by copying the encrypted Apprise URL, never decrypting it — how a new consumer gets the cohort's Slack and Mailgun destinations without anyone handling the secret; `--expect-name` always required, since the target id decides who receives the grant; `--dry-run`; every copy on the credential audit channel, #70), `seed_dev_channels.py` (idempotent sink channels for a dev tenant — a succeeding `syslog://` and a failing closed port; refuses any database not ending in `_dev`, with no production opt-in, #26), `tailnet_bind.sh` (resolve this host's tailnet address, waiting for tailscaled; probes `/proc/net/fib_trie` rather than a netlink client a sandbox can kill silently, and times out non-zero rather than falling back to a bind reachable from elsewhere — observo#473/#479), `serve.sh` (the production launch path, the only place the production uvicorn line is spelled), `sweep.sh` (the one guarded sweep launch path both sweep units ExecStart — sources env files and swaps in `DEV_DATABASE_URL` only under `NOTIFIER_SWEEP_DEV=1`, refuses to run without `NOTIFIER_SECRET_KEY` because otherwise every alert fails at decrypt time while the monitor is still marked missing, delegates the URL check to `src.core.db_safety`), `sweep_monitors.py` (one pass: sweep, commit, and log `checked`/`alerted`/`undeliverable` on every run including the quiet ones, so an operator can tell "nothing is overdue" from "the timer has not fired in a week"), `install_qdrant_key.sh` (merge the shared Qdrant API key into a repo's git-ignored `.claude/settings.local.json` — key on **stdin**, never argv, which `ps` exposes to every other process for the life of the call; atomic replace at 0600 so a crash cannot leave a truncated key that 401s like a wrong one; reports the length and never the value, the only cheap way to tell a truncated transfer from a bad credential; **refuses any target git would commit**, with three distinct messages because a non-work-tree, a tracked path and a missing rule have three different remedies — `.gitignore` does not apply to a tracked path, so that case is a rotation and not a config fix; the check asks `git check-ignore` whatever the rule's *source*, since a global `core.excludesfile` really does prevent a commit from that VM and pinning the rule to the repo's own file is the repo's job, #57, #68), `dump_openapi.py` (dump app.openapi() JSON for SDK regen)
```
